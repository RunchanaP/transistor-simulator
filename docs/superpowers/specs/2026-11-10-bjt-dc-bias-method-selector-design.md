## เป้าหมาย

- ผู้ใช้เลือกได้ว่าผลลัพธ์มาจากวิธีไหน โดย**ค่าเริ่มต้นคือวิธีประมาณ** เพื่อให้เปิดแอปแล้วได้เลขตรงเฉลยทันที
- ทั้งสองวิธีใช้ค่าอุปกรณ์ชุดเดียวกันและผ่าน validation ชุดเดียวกัน
- ผลลัพธ์ทุกค่ามีหน่วย และบอกชัดว่ามาจากวิธีใด

## ไม่ทำ (non-goals)

- ไม่เพิ่มวิธีอื่น (Superposition, Iterative, SPICE)
- ไม่เปลี่ยนค่าอุปกรณ์หรือสมการของ handout
- ไม่แตะ cutoff/saturation logic นอกจากการใช้ VCE ของวิธีที่เลือก
- ไม่แก้ UI ส่วนอื่น (สองคอลัมน์, palette, SVG)

## ทางเลือกที่พิจารณา

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| A. ใช้วิธีประมาณอย่างเดียว | ตรงเฉลย, เรียบง่าย | มองไม่เห็นว่าวิธี exact ต่างอย่างไร, ทิ้งงานที่ตรวจมาแล้ว |
| B. แสดงสองวิธีพร้อมกัน | เห็นความต่างชัด | ตารางกว้าง, เพิ่ม test มาก, เลือกไม่ถูกว่าค่าไหนคือคำตอบ |
| **C. ปุ่มเลือกวิธี (เลือก)** | ตรงเฉลยโดยปริยาย, ยังเก็บวิธี exact ไว้, ผู้ใช้ควบคุมได้ | เพิ่ม input 1 ชุดที่ handout ไม่ได้ขอ |

**เลือก C** เพราะผู้ใช้ต้องการทั้งความตรงเฉลยและความยืดหยุ่น

## สมการสองวิธี (ค่าอุปกรณ์ตัวอย่าง)

| ปริมาณ | Approximate (ค่าเริ่มต้น) | Exact (Thevenin) |
|---|---|---|
| VTH | `VCC·R2/(R1+R2)` = 2.1639 V | เท่ากัน |
| RTH | ไม่ใช้ | `R1R2/(R1+R2)` = 18.03 kΩ |
| VB | `VTH` = 2.1639 V | `VE + VBE` = 1.9422 V |
| VE | `VB − VBE` = 1.4639 V | `IE·RE` = 1.2422 V |
| IE | `VE/RE` = 1.4639 mA | `(β+1)IB` = 1.2422 mA |
| IC | `≈ IE` = 1.4639 mA | `βIB` = 1.2299 mA |
| IB | `IC/β` = 14.64 µA | `(VTH−VBE)/(RTH+(β+1)RE)` = 12.30 µA |
| VC | `VCC − IC·RC` = 8.7794 V | 9.2943 V |
| VCE | `VC − VE` = 7.3154 V | 8.0522 V |

## การตัดสินใจ (ของผม ในฐานะผู้สร้าง)

1. **ค่าเริ่มต้น = approximate** — กำหนดใน `app.py` เมื่อไม่มี/ไม่ถูกต้องของ `method`
2. **`IC = IE` ในวิธีประมาณ** ตามบทเรียน (เฉลยได้ 1.46 mA) ทำให้ `IE = IC + IB` ไม่จริง
   ตรง ๆ ในวิธีนี้ — เป็นราคาของการประมาณ และจะเขียนบอกในหมายเหตุใต้ผลลัพธ์
3. **`IB = IC/β`** ในวิธีประมาณ
4. **Region logic ใช้ร่วมกัน**: `VTH ≤ VBE` → cutoff (กระแสศูนย์), `VCE ≤ 0.3` → saturation
   โดยใช้ VCE ของวิธีที่เลือก
5. **API**: `solve_dc_bias(inp, method=METHOD_APPROX)` — `BiasResult` เพิ่มฟิลด์ `method`
6. **Steps block** เปลี่ยนตามวิธี และไม่แสดง RTH ในโหมด approximate
7. **ป้ายกำกับผลลัพธ์** ระบุว่าคำนวณด้วยวิธีไหน เพื่อไม่ให้สับสนเมื่อสลับ

## ยอมรับได้เมื่อ

- เลือก Approximate → VB 2.164, VE 1.464, IC 1.464 mA, VCE 7.315 V (ตรงเฉลย)
- เลือก Exact → ค่าเดิมทุกตัว (VB 1.942, IC 1.230 mA, VCE 8.052 V)
- ไม่ส่ง `method` มา → ได้ approximate
- `method` ค่าแปลก ๆ → ได้ approximate และหน้าไม่ล้ม
- validation/cutoff/saturation ยังทำงานเหมือนเดิมทั้งสองวิธี
- test suite เขียวทั้งหมด และมี test แยกของแต่ละวิธี

## สิ่งที่เหลือให้ผู้สร้างตัดสิน

- ตำแหน่งปุ่มเลือก (เหนือช่องกรอก) และข้อความกำกับภาษาไทย
- จำนวนทศนิยมของแต่ละค่า (คงเดิม: V 3 ตำแหน่ง, µA 2 ตำแหน่ง)
- จำนวน test ที่เพิ่ม
